# Git Graph for Codex

在 Codex Desktop 的任务侧面板中，交互式浏览当前 Git 仓库。当前版本：0.3.0。

- 提交关系图、本地及远程分支、标签筛选。
- 文件监听驱动的自动刷新；原生 Incoming/Outgoing 同步范围与提交图元素。
- 搜索已加载的提交，查看提交详情、文件差异及合并父节点。
- Monaco 单文件历史 diff：行内／并排视图、差异跳转和未修改区域折叠。
- 跟随 Codex 的颜色、字体与主题，支持窄面板和键盘导航。
- 全界面支持简体中文与英文，自动跟随宿主或浏览器语言并即时切换，保留编辑器阅读位置。
- 首次读取与切换仓库显示骨架屏；历史、提交详情、差异和文件操作分别就地显示错误与重试，宿主能力和布局错误独立显示。
- 插件列表与任务侧面板使用统一的 Git 分支图标，适配浅色、深色主题。
- 提交详情在选中提交下方原位展开，分支线贯穿详情；左侧文件列表、右侧 diff。
- 真实提交的信息限制最大高度并支持内部滚动；同步范围没有提交信息区，直接显示文件列表与 diff；零文件变更显示居中占位符，详情高度和文件列表宽度可拖动调整。
- 分区尺寸与详情放大状态跨任务、重启及插件更新保留。
- 默认使用当前任务目录及 linked worktree；所属 Codex 仓库、分支和合并提交的父提交选择统一使用 `select.tsx` 组件及 `styles.css` 中的统一样式，复用原生选择、键盘交互、标签截断和菜单样式。项目包含多个 Git 仓库时，可在名称处切换。
- 宿主支持时，可将工作区当前文件打开到 Codex 原生文件面板。

所有 Git 操作只读，不执行 fetch、checkout 或 commit。每次加载 250 条提交，可继续加载；搜索覆盖已加载的历史。差异编辑器首次查看文件差异时按需加载。

## 通过 GitHub 安装

需要支持插件市场和 MCP Apps 任务侧面板的 Codex Desktop、Node.js 20.11+ 和 Git。`node` 与 `git` 必须在 Codex 可用的 PATH 中；任务仓库识别需要支持 `thread/read`、`project/read` 和 `thread/attachment/list` 的 Codex app-server。私有仓库需要本机 Git 具有相应的 GitHub 读取权限。

```sh
codex plugin marketplace add https://github.com/mossgowild/codex-git-graph-plugin.git
codex plugin add git-graph@codex-git-graph
```

仓库包含已构建的 `dist/`，安装时无需运行 npm。安装后重启 Codex，进入目标仓库的任务，在右侧面板“新建标签页”中选择 Git Graph。新任务会加载新安装的插件。

如果此前曾用 `codex mcp add git_graph` 手动注册开发版，在插件安装成功后执行一次 `codex mcp remove git_graph`，避免重复入口。

更新：

```sh
codex plugin marketplace upgrade codex-git-graph
codex plugin add git-graph@codex-git-graph
```

卸载：

```sh
codex plugin remove git-graph@codex-git-graph
```

市场采用 [OpenAI 官方插件目录格式](https://developers.openai.com/plugins/build/plugins)。已通过上述 GitHub 链接完成安装，并由 Codex app-server 验证插件身份、任务侧面板入口、目标仓库、非 Git 目录及默认任务目录。

## 操作与边界

任务包含多个 Git 工作树时，顶部名称变为与分支筛选同样式的下拉菜单；单仓库保持普通名称。仓库和分支筛选分别使用 Codex 原生文件夹、分支图标提示用途；同名工作树显示完整路径，非 Git 目录不列出。仓库识别对照 Codex Desktop 26.917.62051：通过宿主工具调用的任务 ID 读取 `thread/read`、Desktop 的 `thread-workspace-state-v1`、所属项目的 `project/read` 和分页的 `thread/attachment/list`。待应用的目录优先；运行环境和已应用目录提供实际工作区，任务 cwd 决定默认仓库。无项目的任务使用自身 cwd；未提供任务 ID 且没有选中项目时使用进程工作目录，不固定退回 Home。尚未持久化的新任务仍可读取当前选中的本地项目；旧任务关联使用 Desktop 项目 ID 映射。

每个目录只向上定位 Git 根，不递归扫描子目录。相同工作树下的多个项目目录合并显示；项目源目录映射到实际运行的 worktree，同一公共 Git 目录下的不同运行工作树保持独立身份。任务附加的工作树按 `workspaceRoot` 定位仓库。读取失败明确显示；任务上下文失败时不会使用其他任务的进程目录。插件优先遵循显式 `CODEX_CLI_PATH`，其次复用启动 MCP 的父 app-server 程序，或 macOS 宿主内置 Node 路径对应的 Codex；其余环境使用 PATH 中的 `codex`。附件接口不可用时明确提示。

刷新会重新读取目录和附件，保留仍有效的仓库选择，否则回到任务的默认仓库。切换只影响当前 Git Graph 面板；历史、详情、diff 与工作区文件打开共同使用所选工作树，清空搜索、分支筛选及详情，保留面板布局。切换失败恢复原仓库并提供重试，过期响应不会覆盖新选择。

面板可见时，通过 Node 文件系统事件监听工作树和真实 Git 元数据目录，支持 linked worktree 的私有 Git 目录及共享引用。MCP 调用等待事件，空闲时每 20 秒续接等待，不执行周期 Git 查询。批量事件合并后按需更新，保留仍有效的历史范围、选择、阅读位置与编辑器；相同差异内容不会重建模型。隐藏、关闭或切换仓库时停止本面板的监听，重新可见时重新建立监听并读取当前状态。监听失败就地显示原因与重试，不自动降级为 Git 定时扫描。操作系统可能漏报文件事件，重新打开、重新可见和手动刷新可校准当前状态。

提交图按 VS Code 原生 SCM Graph 的语义显示：不提供未提交节点，不读取工作区内容代替历史。当前与上游引用分歧且有共同祖先时，按筛选和已加载提交插入 Incoming/Outgoing Changes；Outgoing 在当前 HEAD 前，Incoming 在共同祖先前，未加载必要连接行或原生已合并特殊场景时不补假行。聚合行没有提交数量、引用或头像，比较范围分别为共同祖先到本地/上游的完整净变化。状态只依据已有本地引用，插件不执行 fetch、push 或 pull。base 引用按已有 VS Code 缓存配置、分支/HEAD reflog 来源及其上游、默认远程的 symbolic HEAD 只读解析，不写 Git 配置或猜测 main/master。

提交列表与详情标题的引用标签显示原生 Codicons：当前引用为 target，本地分支为 git-branch，远程分支为 cloud，标签为 tag。图标继承标签颜色，实际图形以 cloud 的约 10px 可见高度居中。列表显示主要引用名称，其余有色引用按颜色和图标分组为图标／计数；无关联色的引用只在详情显示，详情保留全部名称。引用区按内容优先分配宽度，极窄时可横向滚动，聚焦提交行时用左右方向键查看；名称搜索保留完整集合，分组命中高亮图标／计数并定位，隐藏引用命中打开详情。主要引用长名称使用截断提示，分组提示包含完整引用。

提示复用 Codex 26.917 的 Banner 图标、3xl 连续圆角（默认 20px，桌面连续圆角缩放后 25px）、0.5px 轮廓、16/20/12px 内边距及语义颜色，正文行高为字号的 1.625 倍，放在对应操作栏下方；重试按钮使用原生描边胶囊样式，随提示容器宽度在 560px 处换行。空目录、空历史、零文件变更和不可比较文件共用 Codex 审查空态的原始 66×73 SVG（显示高度 72px）、标题及说明排版，说明文字使用正文色的 65% 透明度，文案各自对应真实状态。零文件变更时在整个变更区域居中，不保留空文件列表或分隔线。骨架屏和错误不会误显示为空态。缺少的原生提示底色与插图颜色通过已有外观配置读取补齐，随亮暗主题、对比度与字体调整。

悬浮提示对齐 Codex Desktop 26.924.22138：浅色主题使用深底浅字，暗色主题使用不透明控件底色；采用 2xl 连续圆角、1px 低对比边框、5/12px 内边距和 18px 行高，字体、颜色和圆角跟随宿主设置。最大宽度对应原生 20rem 的 320px，并根据窗口可用空间限宽、限高。提示仅用于图标操作说明、被截断的文字及完整路径、SHA、重命名前路径等补充信息；提交整行、列表容器和分隔线不触发提示。提示通过浏览器 Popover 顶层显示，鼠标悬停延迟 200ms，键盘聚焦即时显示，支持 Escape 关闭、鼠标移入提示及窗口边缘避让。搜索清除使用可聚焦的独立按钮，清空后将焦点交回输入框。审查搜索框、Banner 和空态已复核新版；详情卡片保留已验收的边界及间距。

Codex 原生审查还可显示任务保存的上一轮 diff，因此无 Git 仓库也可能有对比内容。Git Graph 浏览 Git 历史，不将任务 diff 当作仓库，也不额外扫描 Home。

点击提交查看变更文件，方向键切换文件及 diff。关闭详情后保留选中提交并恢复焦点；刷新不会重新展开已关闭的详情。刷新后仍在加载范围内的提交保留所选对比父节点和文件。搜索框复用 Codex 审查文件筛选框的 28px 高度、lg 连续圆角、1px 边框、2.5% 前景色底色、14px 字号和 18px 行高。搜索栏默认隐藏，右上角搜索按钮切换显示，⌘/Ctrl+F 展开并聚焦搜索框；Escape 收起搜索栏并回到按钮，保留关键词，隐藏时不高亮匹配项。搜索按实际命中文字高亮并计数：普通命中使用宿主焦点色的 20% 透明背景，当前命中提升到 32%，文字保持宿主正文色并使用宿主小圆角，标题不整行变色。若只命中隐藏的 SHA 或邮箱，会显示带高亮的简短上下文。搜索框支持 Enter 跳转和 Shift+Enter 反向跳转，按命中位置循环；同一提交中的不同命中不会折叠详情。

文件差异由 Monaco Diff Editor 显示；历史提交从 Git 对象读取两侧完整历史内容，不读取当前工作区内容来代替历史版本；同步范围按两端真实提交 SHA 比较。新增和删除文件以空的一侧表示，重命名使用各自版本的路径，文件模式变化及子模块提交也会显示。文本按 UTF-8 读取，单侧超过 2 MiB、二进制或非 UTF-8 文件会显示说明，不截断后继续比较。仅换行符或 BOM 不同会明确提示。差异工具栏的图标按钮切换行内／并排视图，图标及提示表示点击后的目标视图；详情标题栏的放大按钮为差异腾出空间，暂时隐藏其他提交；放大后详情填满剩余高度，顶部保留 2px、底部保留 4px 间距，图标变为恢复，再次点击还原布局；差异区域内 ⌘/Ctrl+F 搜索文件。编辑器为只读，界面与 diff 增删配色、代码字体族和代码字号跟随宿主；语法高亮继承 Monaco 原生亮暗主题（vs／vs-dark），普通文字使用宿主前景色；代码字体读取宿主 `--font-mono`；按钮、下拉项及提交行的悬停色统一引用顶层 `--color-background-primary-ghost-hover`，Monaco 的非活动选区、其他搜索命中、输入选项和按钮悬停也映射该变量；该变量依据 Codex Desktop 26.917 的主题前景色与对比度公式，通过同一次只读配置读取补齐，随亮暗主题切换。代码字号通过只读 `config/read` 获取 `desktop.codeFontSize`（未配置时使用 Codex 默认 12px）。打开详情、宿主主题更新、重新聚焦时重新检查；详情可见时每 5 秒检查配置文件变化，未变化时复用缓存。读取失败明确提示并可重试。行高随字号由 Monaco 计算，编辑器内部控件与图标保持默认，不应用宿主圆角覆盖。差异模式按钮的红绿图形使用宿主删除／新增语义色，编辑器浮层阴影颜色取自宿主 `--shadow-lg`，随主题更新；搜索与差异导航使用同一组原生大号上下箭头。编辑器代码和 Worker 随插件打包，无需访问 CDN。

提交列表保持插件的 30px 行高、内缩圆角悬停和选中背景、引用徽标在标题前、作者在右侧，没有行尾动作按钮。左侧图保留原生语义：普通提交为实心点，HEAD 为空心环并优先于合并形状，多父提交为双圆中心，Incoming/Outgoing 使用 4,2 虚线圆，悬停或选中时线宽从1px加粗到3px，与HEAD有效彩色环等厚并保留虚线，泳道为11px、连线为1px实线。节点、线和base颜色来自宿主主题，按行裁切；展开只加粗自身通向父节点的末段。同步范围不显示消息、作者、日期及提交信息分隔条，范围读取失败仍显示错误与重试；切回真实提交恢复已保存的摘要高度。详情、文件列表、控件、通知、tooltip及布局偏好沿用Codex样式。

点击提交或同步行查看完整净变化文件列表，再选择一个文件查看只读diff。没有Open Changes按钮或内嵌多文件模式；普通/合并提交保留父选择器，根提交比较空树到root，Incoming/Outgoing分别比较共同祖先到上游/当前SHA。单文件编辑器使用稳定DOM，普通文件切换和详情关闭/重开保留实例。

变更文件支持列表／树形视图切换，默认列表，全插件记忆上次模式。树形视图按目录优先、名称排序，目录初始展开，可用鼠标或左右方向键折叠／展开，上下方向键及 Home／End 移动；进入文件时更新单文件 diff。折叠目录、切换模式和刷新保留已选文件与 diff，切换回树形时展开该文件的祖先目录。目录展开状态只保留在当前详情，不写入偏好；查看其他仓库或重新打开面板使用同一保存模式。

界面语言优先使用MCP HostContext.locale，缺失时使用浏览器首选语言；简体中文映射到zh-CN，其余未支持语言使用英文。宿主或浏览器语言变化后，按钮、提示、无障碍名称、日期、搜索和已有自有错误即时更新；提交内容、作者、分支、路径及原始Git/系统诊断保留来源原文。中文同步行使用VS Code官方名称“传入的更改”“传出的更改”。错误及不可比较原因以稳定消息键和参数传递，不通过替换已显示文字实现翻译。

Monaco使用官方中文语言表及内置英文文案，中英API各按需初始化一次。语言变化时重建当前编辑器并恢复阅读、选择、滚动和文本焦点；普通同语言生命周期保持实例。主题与字体同步两套已加载API，沿用原生vs/vs-dark语法高亮。两套runtime的服务和样式在当前视图内固定保留；编辑器、模型及worker随语言重建释放，不在每次切换追加整套模块。语言资源失败就地显示可重试错误，过期加载不会覆盖最新语言。

切换筛选期间暂停旧列表和搜索交互；读取失败会恢复原筛选，重试仍针对请求的筛选。所选分支或标签被删除后，重新加载全部历史并明确提示。不显示底部状态栏；还有历史记录时，滚动列表末尾显示“加载更多”，全部加载后不占用空间。分页使用固定提交快照；若发现分支、标签或 HEAD 变化，会从当前引用恢复已加载范围和仍可达的阅读锚点，避免混用旧历史和新引用。

点击提交，在该行下方展开唯一的详情区；再次点击同一提交或按 Escape 关闭，切换提交时详情随之移动。展开处的分支线与下一条提交保持连接。提交行使用内缩圆角选中背景，跟随宿主中性控件色。详情使用宿主次级背景色，普通状态上下各保留 2px 留白；卡片左边框对齐该提交行文字区起点，右边框对齐作者文字区右边缘，与时间线区分。详情顶部的提交 SHA 是普通标题，不折叠整张卡片；提交信息直接显示，不设折叠标题，默认短内容按自然高度显示，最高 160px 且不超过常规卡片高度的三分之一，超出时内部滚动；拖动提交信息下方横向分隔线可调整与变更文件区域的高度分配，并跨任务保存；“变更文件”是普通标题，有变更文件时显示左侧文件列表和右侧 diff。文件列表与中间分隔线保留间距，右侧 diff 紧贴分隔线。分区标题没有点击或悬停行为；右侧操作按钮独立生效。卡片底部不设内部分割线，仍可拖动外边缘调整整张卡片高度；文件列表右边调整宽度。详情放大时保留选中提交及详情，隐藏其他提交和搜索框；再次点击放大按钮恢复历史列表。

分隔线使用宿主主题色和两端渐隐高亮，支持 Tab 聚焦、对应方向键调整 8 px、Shift + 方向键微调 1 px、双击或 Home 恢复默认、Escape 取消拖动。尺寸和详情放大状态跨任务保留；窄窗口限制文件列表宽度，为右侧 diff 留出空间，回到宽窗口后恢复已保存宽度。时间线纵向滚动，标题、作者与徽标在窄窗口中省略显示，详情宽度随可视区域调整。

布局只写入插件数据目录 `~/.codex/plugins/data/git-graph-codex-git-graph/`：`panel-layout.json` 保存分区尺寸、详情放大状态和 `fileView` 文件视图模式。旧版 `column-widths.json` 文件保留原样，不再读取、校验或写入；紧凑列表不应用列宽。使用 `CODEX_HOME` 时跟随该目录；不写入仓库或 Codex 设置。所有任务共享最近一次保存的布局，已经打开的其他面板在重新打开时读取更新。保存失败会显示错误并提供重试，当前文件视图与 diff 保持可用。

“在 Codex 中打开工作区文件”打开的是当前内容。不存在的历史文件仍可在 Git Graph 内查看差异；服务器拒绝打开指向仓库外的符号链接及非普通文件。

指定历史提交暂不能交给原生审查面板：当前宿主接口不接受任意提交 SHA 或合并父节点。任务侧面板入口与原生文件打开使用实验性宿主扩展，已对照 Codex Desktop 26.908.40834；后续版本可能需要适配。真实 Codex 窗口的最终视觉效果和原生文件打开仍待用户验证。

## 开发

```sh
git clone https://github.com/mossgowild/codex-git-graph-plugin.git
cd codex-git-graph-plugin/plugins/git-graph
npm ci
npm run typecheck
npm run build
npm test
npm run test:launcher
```

手写运行、构建和测试源码统一使用 TypeScript。`ui.tsx` 使用 Preact 管理页面、异步状态、搜索高亮和局部提示，`select.tsx` 声明原生选择控件；`panels.ts` 负责尺寸计算和交互，Preact 渲染布局状态。唯一详情通过固定门户容器移入提交槽位，关闭时停放；`diff-editor.ts` 只管理 Monaco 容器内部、模型与主题，并把计算状态回传 Preact。

手写 CSS 统一放在 `styles.css`，使用 Tailwind CSS 4.3.3；`@theme inline` 将 Codex 运行时的颜色、字体、字号、间距与圆角映射为工具类，详情面板仍按自身作用域解析背景。布局和状态类放在 Preact 标记中，共用控件及原生 select 伪元素保留必要的 CSS 和 `@apply`。不引入 Preflight 或 Tailwind 默认配色、字体与圆角；Monaco 的 `dist/editor.css` 由构建自动生成，无需手工维护。构建时通过 Tailwind CLI 编译并内嵌 CSS，源码扫描仅包含 `ui.tsx` 和 `select.tsx`，无需 CDN 或运行时 Tailwind。

`npm run typecheck` 严格检查 `.ts`/`.tsx` 源码，esbuild 负责打包；构建和测试通过 `tsx` 运行，最低支持 Node.js 20.11。安装后的插件只运行 `dist/server.mjs`，无需 TypeScript、tsx 或安装依赖。

源码和构建产物都在 `plugins/git-graph/`；仓库市场入口位于 `.agents/plugins/marketplace.json`。发布修改时一起提交更新后的 `dist/` 和 `.mcp.json`。图布局及 SVG 基于 VS Code 内置 SCM Graph 的 MIT 源码适配，第三方 SDK 负责 MCP 和宿主通信。插件自身的按钮与菜单图标直接使用 Codex 26.915.31945 的原始 SVG 路径（`app-shared-8f4fbb856ceb.js`），行内/并排按钮使用 `code-diff-e1ff49b978eb.js` 的原始双色图标；新增提示图标和空态插图取自 Codex 26.917.62051 的共享 Banner 与审查 EmptyState；Monaco 内部图标保持默认。界面图标定义于 `icons.tsx` 和 `styles.css`，构建后统一内嵌，分支入口图标源文件位于 `assets/`，插件清单引用 SVG，构建时将同一组图标内嵌到 MCP `serverInfo.icons`，不发起图标网络请求。

当前 Codex 兼容格式不会展开 MCP 参数中的 `${PLUGIN_ROOT}`。构建脚本按插件清单版本生成启动命令，从 `CODEX_HOME`（未设置时为 `~/.codex`）下的 `plugins/cache/codex-git-graph/git-graph/<version>/` 加载插件，保持进程工作目录为当前任务目录。这依赖 Codex 的缓存目录结构；以后宿主支持直接传入插件路径且保留任务目录时应替换。修改清单版本后需要重新构建；不要单独复制 `.mcp.json` 到别的市场。

测试还覆盖原生同步范围、base 与同名分支/标签、只读范围文件打开、路径与文本边界、引用改写后的可达锚点、原生文件监听、跨任务/面板隔离、空闲不查询 Git、取消/租期、stdio EOF 关闭，以及真实 Git 历史、合并父节点、特殊路径和重命名、分页、只读状态、任务仓库隔离、文件定位边界、祖先汇合与轨道连续、引用语义颜色与顺序、UI 缓存标识、布局跨进程保存和设置参数校验。

浏览器回归检查使用 `npm run test:ui`；Playwright 已作为开发依赖声明，首次运行前执行 `npm install` 并安装其 Chromium。也可通过 `PLAYWRIGHT_MODULE` 指向现有 Playwright 的模块入口，通过 `PLAYWRIGHT_CHROMIUM` 指向现有浏览器可执行文件。检查会在临时数据目录中覆盖详情原位展开、分支线连续、文件与 diff 左右布局、Codex 行布局与分区拖动、键盘调整、取消、详情放大恢复、宽窄屏切换、跨会话布局恢复和错误重试，不修改个人布局。还检查提示归属与并存、字号错误恢复、打开文件失败及详情和编辑器 DOM 跨切换/关闭重开的身份保持。另使用临时 Git 仓库覆盖筛选失败与重试、删除筛选引用后的恢复、分页期间引用变化、刷新时父节点与文件选择保留、引用重名、diff 内容着色及乱序响应。

文件视图检查复用这些隔离仓库与偏好，覆盖默认列表、嵌套目录及同路径文件／目录、树形键盘操作、折叠与模式切换保留选中 diff 和编辑器资源、保存失败重试、中英动作标签、跨仓库与重开记忆；同步范围也检查树形视图与刷新保留。

`npm run test:ui -- --live-only` 用真实临时仓库、打包 MCP 服务与原生 fs.watch 检查监听续接、真实 Incoming/Outgoing、共同祖先分页门槛、范围文件列表/逐文件diff、文件与编辑器保持及错误恢复。宿主为测试 AppBridge；该检查不能代替实际 Codex 的等待、关闭或原生文件打开验收。

`npm run test:ui -- --locale-only` 使用真实隔离仓库验证语言来源、已有错误与日期、同步行和搜索、Monaco原生查找、十轮语言切换的阅读/焦点/资源边界、亮暗/字体及异步最新语言。测试HostContext不能代替实际Codex的locale传递证明。

`npm run test:launcher` 将当前构建的 `dist/` 文件复制到临时 `CODEX_HOME` 缓存，用生成的 `.mcp.json` 命令启动；同时校验无项目时使用启动目录、HTML 资源及按需编辑器资源，缓存中不包含源码和 `node_modules`。

在本机已安装当前清单版本后，运行 `npm run test:installed` 可额外检查实际缓存中的启动程序，确认没有本地项目时使用启动目录；该检查不会安装插件或修改 Codex 配置。
